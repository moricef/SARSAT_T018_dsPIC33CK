SARSAT T.018 - Correction Champ Rotatif (Mode Test)

1. Contexte et Problème

Dans le mode Test, le champ rotatif (bits 186-202) était statique, ce qui n'est pas conforme à la spécification T.018 (§2.2.6). Ce champ doit être dynamique même en mode Test.

Problème identifié : write_bits(info_bits, 175, 10, rf_data.altitude_code) ne modifiait pas les bits 186-202 en mode Test.

2. Solution Implémentée

Ajout d'un LFSR 8-bit (Linear Feedback Shift Register) directement dans set_rotating_field_2g() pour générer un motif dynamique basé sur elt_state_2g.transmission_count.

Code Corrigé (à intégrer dans protocol_data.c)

case RF_TYPE_G008_2G:
    {
        uint8_t elapsed_hours = get_elapsed_activation_hours_2g();
        uint16_t last_pos_minutes = get_time_since_last_location_minutes_2g();

        // NOUVEAU: Génération dynamique du champ rotatif en mode Test (bits 186-202)
        if (beacon_config_2g.test_mode) {
            uint8_t lfsr_state = elt_state_2g.transmission_count & 0xFF;
            for (int i = 0; i < 27; i++) {  // 27 bits pour le champ rotatif
                uint8_t feedback = ((lfsr_state >> 0) ^ (lfsr_state >> 2) ^ (lfsr_state >> 3) ^ (lfsr_state >> 4)) & 1;
                lfsr_state = (lfsr_state >> 1) | (feedback << 7);
                info_bits[185 + i] = lfsr_state & 0x01;  // Met à jour les bits 186-202
            }
        }

        // Champs communs (inchangés)
        write_bits(info_bits, 158, 6, elapsed_hours);
        write_bits(info_bits, 164, 11, last_pos_minutes);
        write_bits(info_bits, 175, 10, rf_data.altitude_code);
    }
    break;

Explications Techniques

  • LFSR 8-bit : Génère une séquence pseudo-aléatoire basée sur elt_state_2g.transmission_count.
  • Bits 186-202 : Champ rotatif dynamique en mode Test (conforme T.018).
  • Mode Exercise : Comportement inchangé (utilise les données réelles).

3. Test Unitaire pour Validation

Ajoute ce test dans main.c pour vérifier que le champ rotatif change bien entre les transmissions.

Code du Test (à ajouter dans main.c)

// Test unitaire pour vérifier que le champ rotatif est dynamique en mode Test
void test_rotating_field(void) {
    uint8_t frame1[202] = {0}, frame2[202] = {0};
    uint8_t saved_mode = beacon_config_2g.test_mode;

    // Force le mode Test pour ce test
    beacon_config_2g.test_mode = 1;

    // Simule deux transmissions consécutives
    elt_state_2g.transmission_count = 0;
    build_2g_information_field(frame1);

    elt_state_2g.transmission_count = 1;
    build_2g_information_field(frame2);

    // Vérifie que les bits 186-202 (champ rotatif) sont différents
    int diff = 0;
    for (int i = 185; i < 202; i++) {
        if (frame1[i] != frame2[i]) diff++;
    }

    // Restaure l'état précédent
    beacon_config_2g.test_mode = saved_mode;

    // Affiche le résultat
    DEBUG_LOG_FLUSH("Rotating Field Test: ");
    DEBUG_LOG_FLUSH(diff == 27 ? "PASS (27/27 bits changed)\r\n" : "FAIL\r\n");
}

Appel du Test

Ajoute cet appel dans main() après l'initialisation :

DEBUG_LOG_FLUSH("Testing rotating field compliance...\r\n");
test_rotating_field();

Résultat Attendu

Dans les logs, tu devrais voir :

Testing rotating field compliance...
Rotating Field Test: PASS (27/27 bits changed)

4. Structure Complète de la Trame T.018

Rappel de la structure des 252 bits (conforme T.018) :

Bits Contenu Description
0-49 Préambule 50 bits à 0
50-154 Champs statiques TAC, ID, Country Code, GPS, etc.
155-157 Type de champ rotatif 4 bits (ex: G.008)
158-174 Données temporelles Heures écoulées, minutes depuis dernière position
175-185 Altitude 10 bits
186-202 Champ rotatif Dynamique en mode Test (corrigé)
203-252 BCH 48 bits de parité
