Correction des Champs Rotatifs en Mode Test (SARSAT T.018)

1. Problème Identifié

Dans le mode Test, le champ rotatif (bits 155-202) est statique, ce qui n'est pas conforme à la spécification T.018. Ce champ doit être rotatif même en mode Test pour garantir la conformité.

Impact : Un récepteur conforme pourrait rejeter la trame car elle ne respecte pas le standard.

2. Solution Proposée

Générer un motif rotatif pour les bits 155-202, même en mode Test. Plusieurs options sont possibles :

  • Compteur incrémental : Simple et efficace.
  • Motif pseudo-aléatoire : Plus réaliste, mais plus complexe.
  • LFSR simplifié : Pour un motif déterministe mais variable.

3. Implémentation pour dsPIC33CK

3.1. Modification du Code Existante

Dans le fichier protocol_data.c, modifier la fonction de génération des trames pour inclure un champ rotatif dynamique.

3.2. Exemple de Code (Compteur Incrémental)

// Dans protocol_data.c
void generate_rotating_field(uint8_t *frame, uint16_t burst_count) {
    // Génère un motif rotatif basé sur le numéro du burst
    for (int i = 0; i < 48; i++) {
        frame[155 + i] = (burst_count + i) & 0x01;  // Bit 0 ou 1 en alternance
    }
}

void build_frame(sarsat_frame_t *frame, uint16_t burst_count, uint8_t mode) {
    // Remplir le préambule et les champs statiques...
    generate_rotating_field(frame, burst_count);  // Champ rotatif dynamique
    // Remplir le BCH...
}

3.3. Exemple de Code (LFSR Simplifié)

Pour un motif plus réaliste, utiliser un LFSR 8-bit (simple et efficace) : 

// LFSR 8-bit pour générer un motif pseudo-aléatoire
uint8_t lfsr_8bit(uint8_t state) {
    uint8_t feedback = ((state >> 0) ^ (state >> 2) ^ (state >> 3) ^ (state >> 4)) & 1;
    return (state >> 1) | (feedback << 7);
}

void generate_rotating_field(uint8_t *frame, uint16_t burst_count) {
    uint8_t lfsr_state = burst_count & 0xFF;  // Initialiser avec le numéro du burst
    for (int i = 0; i < 48; i++) {
        lfsr_state = lfsr_8bit(lfsr_state);
        frame[155 + i] = lfsr_state & 0x01;  // Bit 0 du LFSR
    }
}

4. Implémentation pour ODROID-C4/PlutoSDR

4.1. Adaptation en C (ODROID-C4)

Le même principe s'applique sur l'ODROID-C4. Voici un exemple en C : 

#include <stdint.h>

// Structure de la trame
typedef struct {
    uint8_t preamble[50];
    uint8_t info[202];
    uint8_t bch[48];
} sarsat_frame_t;

// Génère un champ rotatif avec un LFSR 8-bit
void generate_rotating_field(uint8_t *frame, uint16_t burst_count) {
    uint8_t lfsr_state = burst_count & 0xFF;
    for (int i = 0; i < 48; i++) {
        uint8_t feedback = ((lfsr_state >> 0) ^ (lfsr_state >> 2) ^ (lfsr_state >> 3) ^ (lfsr_state >> 4)) & 1;
        lfsr_state = (lfsr_state >> 1) | (feedback << 7);
        frame[155 + i] = lfsr_state & 0x01;
    }
}

// Exemple d'utilisation
int main() {
    sarsat_frame_t frame;
    generate_rotating_field(frame.info, 0);  // Premier burst
    return 0;
}

4.2. Adaptation en Python (Prototypage)

Pour un prototypage rapide sur l'ODROID-C4 : 

def generate_rotating_field(burst_count):
    lfsr_state = burst_count & 0xFF
    field = []
    for _ in range(48):
        feedback = (lfsr_state ^ (lfsr_state >> 2) ^ (lfsr_state >> 3) ^ (lfsr_state >> 4)) & 1
        lfsr_state = ((lfsr_state >> 1) | (feedback << 7)) & 0xFF
        field.append(lfsr_state & 1)
    return field

# Exemple d'utilisation
rotating_field = generate_rotating_field(0)  # Premier burst
print(rotating_field)

5. Validation

Pour valider que le champ rotatif est correctement généré :

  1. Simuler plusieurs bursts : Génère 10 bursts consécutifs et vérifie que le champ rotatif change à chaque fois.
  2. Vérifier la conformité : Utilise un analyseur logique ou un script pour vérifier que les bits 155-202 ne sont pas statiques.
  3. Tester avec un récepteur SARSAT : Si disponible, vérifie que le récepteur accepte les trames en mode Test.
